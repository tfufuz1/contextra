## 2. Auswirkungen auf Index §3.3 und §4

- **Lock-Ränge (Index 3.3):** unverändert. Zusätzlich gilt: Rang 150 wird nie über einen `StoreIo`-Aufruf mit Dauer > 5 ms gehalten. Ein `fsync` darf unter 150 stehen, ein Datei-Rewrite nicht.
- **CI-Gate G-4 (Index 3.7):** Ausnahme-Regel präzisiert: `std::fs`/`tokio::fs` verboten in `store/src/erasure/`, `engine/src/erasure/`, `vector/src/hnsw/purge*.rs`. Bestehender Code in `manifest/` und `lsm/recovery.rs` ist **nicht** Gegenstand von G-4, bis WP-3.6 ihn umstellt (03 §10).
- **Testbarkeit (Index 6 Nr. 2):** `FaultVfs` implementiert weder `open`/`VfsFile` noch `rename`, ihr `sync_dir` ist ein No-op (`testkit/src/fault_vfs.rs:239-307`) ✔. CP-1 … CP-18 sind damit **nicht** darstellbar. 13 spezifiziert `CrashVfs` als Voraussetzung für WP-3.
