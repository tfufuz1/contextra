## New Text
Contextra Store recovery and MVCC correctness must be continuously verified via a deterministic, std-only `ReferenceModel` in `contextra-testkit`.
Crash testing operates exclusively through the public `LsmStorage` interface and filesystem byte-level truncation without modifying store production code (`src/`).
Model-based property tests execute randomized operation sequences (`put`, `delete`, `commit`, `rollback`, `flush`, `compact`, `snapshot-pin`, `snapshot-read`) and enforce that:
1. Snapshot queries match `ReferenceModel` expectations at any sequence number $S \le S_{commit}$.
2. All confirmed commits survive crash-and-reopen across any prefix truncation offset of WAL segments.
3. Flush and compaction operations do not mutate visible read state.
