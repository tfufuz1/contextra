# Spec Sync: L01 — Engine API SSI Read-Set Integration

## Section 12.4: Engine Transactional Read-Set Integration & Write-Skew Prevention

### Alter Text
```markdown
`Collection` CRUD and relate operations execute LSM reads via untracked `storage.get` and `storage.get_at_seq`, leaving `ReadSet` empty during transaction execution.
```

### Neuer Text
```markdown
`Collection` transaction-bound CRUD and relationship operations execute LSM point lookups via `get_tracked` and `get_at_seq_tracked` under the active transaction's `TxId`:
- `insert_op`: reads `old_user_val` and `old_doc_val` via `get_at_seq_tracked` and executes collision checks via `get_tracked`.
- `update_op`: reads `old_user_val` and `old_doc_val` via `get_at_seq_tracked` and executes collision checks via `get_tracked`.
- `delete_op`: reads `old_user_val` and `old_doc_val` via `get_at_seq_tracked`.
- `link_memories`: reads target document metadata and user document records via `get_at_seq_tracked`.
- `relate_with_provenance`: reads existing relationship records via `get_at_seq_tracked`.
- `update_document_importance`: allocates `TxId` prior to reading document payload via `get_tracked`.
Non-transactional reads (snapshot search hydration, point lookups in `get`/`get_kv`/`get_links`/`get_community`, and crash recovery repair) remain untracked with explicit `// SSI: nicht tx-gebunden` comments.
All concurrent transactional modifications through `Contextra` / `Collection` / `DbTransaction` enforce serializability and reject write-skew anomalies with `ContextraError::Conflict` or `ContextraError::Transaction`.
```
