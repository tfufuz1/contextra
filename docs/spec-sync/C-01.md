# Spec-Sync Fragment for C-01

## Section Number
§12.4 / DeletionProof Wire Format, Signature Versioning & Python FFI Isolation

## Old Text
`DeletionProof` serializes `signature_version` as an untyped `u8` field defaults to `1`. Verification branches over raw integer values without a formal `SignatureVersion` conversion or explicit fail-closed boundary for invalid version numbers. The Python bindings contain a test panic hook using `panic!` inside `trigger_panic_helper`.

## New Text
`DeletionProof` maintains `pub signature_version: u8` for backwards-compatible wire serialization and JSON serde format, and provides `signature_version_typed() -> Result<SignatureVersion, DeletionProofError>` enforcing typed conversion via `TryFrom<u8>`. `SignatureVersion` variants (`V1 = 1`, `V2 = 2`, `V3 = 3`) are validated fail-closed in `verify()`, rejecting unknown or out-of-range signature versions with `DeletionProofError::UnsupportedVersion(v)`.
In Python FFI bindings, `trigger_panic_helper` uses `std::panic::resume_unwind` with panic containment guaranteed by `run_blocking_ffi` (`std::panic::catch_unwind`), mapping panic unwinds to `PyRuntimeError` and preventing Rust panics from unwinding across FFI boundaries.
