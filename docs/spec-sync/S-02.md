# Spec-Sync Fragment for S-02

## Section Number
§11.4 / Group Commit Path: Chain Security, Batch-Scoped Rollback, and Cancel Safety

## Old Text
During group commit, followers prepare WAL batches individually before queueing, advancing `last_hmac` prior to group aggregation. Upon WAL append failures or participant timeouts, rollback searches for the transaction ID in the WAL via `find_tx_offset` and truncates from that offset, which can cause concurrent durable batch entries to be truncated.

## New Text
During group commit, followers queue raw WAL operations without advancing the HMAC chain. The group leader takes the queued operations upon closing the group commit window and executes batch HMAC chain preparation (`wal.prepare_batch`) ONCE for the aggregated group batch. Before issuing the physical WAL append, an append anchor (`start_offset`, `start_hmac`) is recorded under `truncate_lock`. On WAL append failure, truncation is strictly bounded to the recorded anchor via `wal.truncate(start_offset, start_hmac)`, guaranteeing that foreign or prior durable batch entries are never truncated. If the leader future is dropped or cancelled while waiting in the group commit window, a drop guard drains the pending queue, fails waiting followers gracefully with an explicit error, and releases intent locks and SSI reservations.
