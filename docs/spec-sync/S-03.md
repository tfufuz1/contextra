# Spec-Sync Fragment for S-03

## Section Number
§4.3 / F-30: WAL Legacy HMAC Key Depreciation & Retirement Marker
§3.2 / F-27: Non-blocking WAL Observer Execution & Fail-Open Commit Protection

## Old Text
WAL replay supports fallback to a static obfuscated XOR legacy HMAC key when `allow_legacy_integrity_key_fallback` is enabled. Upon rekeying, a `.rekeyed` text marker is created. Observer notifications execute synchronously on the commit thread with a latency deadline timeout.

## New Text
Static obfuscated legacy HMAC integrity key material is compile-time gated behind the `legacy-wal-key` Cargo feature (disabled by default). Binaries built without `legacy-wal-key` exclude all legacy key material, and legacy migration APIs return explicit storage errors. Successful migration atomically writes a retirement marker containing a Blake3 hash binding the directory identity and the new key material without exposing plaintext key material. Presence of the retirement marker permanently rejects legacy key fallbacks across all opens and replays. Observer notifications offload blocking waits via `spawn_blocking` or `block_in_place` within Tokio runtime contexts, ensuring transaction commit paths on Tokio runtime threads remain non-blocking while enforcing maximum latency deadlines, bounded queues, and circuit breaker protection.
