# Spec Sync: K01 — Effective SSI ReadSet Tracking & Port Interface

## Section 12.3: Serializable Snapshot Isolation (SSI) ReadSet Tracking & Port Interface

### Alter Text
```markdown
StorageEngine provides point-in-time reads via `get` and `scan_prefix`. `LsmStorage` provides tracked point reads via `get_tracked` and `get_at_seq_tracked`.
```

### Neuer Text
```markdown
`StorageEngine` provides dyn-compatible methods `get_tracked`, `get_at_seq_tracked`, `scan_prefix_tracked`, and `supports_ssi_tracking(&self) -> bool`.
Default implementations on `StorageEngine` delegate to untracked reads (`get`, `get_at_seq`, `scan_prefix`) and return `supports_ssi_tracking() == false`.
`LsmStorage` and `TenantScopedStorage` implement `supports_ssi_tracking() == true`:
- `get_tracked` and `scan_prefix_tracked` evaluate `snapshot_seq = last_applied_seq.load(Acquire)` once at invocation start.
- `get_tracked` and `get_at_seq_tracked` register point read keys into transaction `tx_id`'s `ReadSet`.
- `scan_prefix_tracked` registers all visible matching keys into transaction `tx_id`'s `ReadSet` at `snapshot_seq`.
- `TenantScopedStorage` wraps tracked methods with tenant-encoded physical keys and strips tenant prefixes from scanned results.
- Failed WAL commits trigger `ssi_validator.forget_from(first_seq)` to remove pre-registered write keys.
- MemTable flushes trigger `ssi_validator.prune_through(bound_seq)`.
- `LsmConfig` adds `ssi_max_tracked_keys` (default: 1,000,000) to bound committed write key capacity.
```
