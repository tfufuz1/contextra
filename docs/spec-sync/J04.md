# Spec Sync: J04 — Contextra MVCC Enhancements

## Section 12.3: Serializable Snapshot Isolation (SSI)
### Alter Text
```markdown
The SequenceLogSsiValidator tracks committed writes in memory using `committed_writes: Arc<RwLock<AHashMap<Vec<u8>, u64>>>` and prunes historical sequence numbers via `prune_through(bound_seq)`.
```

### Neuer Text
```markdown
The SequenceLogSsiValidator tracks committed writes in memory using `committed_writes: Arc<RwLock<CommittedWrites>>` backed by a sequence BTreeMap index for $O(K_{\text{removed}})$ removal. It provides `forget_from(first_seq: u64) -> usize` to remove committed write key registrations from failed WAL append batches.
Commit key tracking is bounded by `max_tracked_keys` (configured via `new_with_bounds`, defaulting to `DEFAULT_MAX_TRACKED_COMMIT_KEYS = 1_000_000`). If `committed_writes.len() >= max_tracked_keys`, validation fails closed with `ContextraError::Conflict`.
`prune_through(bound_seq: u64) -> usize` returns the count of deleted entries.
`ReadSet` supports range scan phantom protection via `record_prefix(prefix, snapshot_seq)`. SSI validation evaluates point reads directly and checks range prefixes against committed keys matching the prefix.
```

## Section 12.4: Transaction Staging Buffer (`TxBuffer`)
### Alter Text
```markdown
Staging capacity is bounded by `max_ops_per_tx` (default: 10_000 ops).
```

### Neuer Text
```markdown
Staging capacity is bounded by `max_ops_per_tx` (default: 10_000 ops), `max_tx_staged_bytes` (default: 16 MiB per transaction), and `max_total_staged_bytes` (default: 256 MiB globally across all active transactions).
Per-entry overhead is calculated using `STAGING_ENTRY_OVERHEAD_BYTES = 32`.
When byte or ops limits are exceeded, staging operations return `ContextraError::Storage("Staging budget exceeded")` or `ContextraError::Transaction`.
Staged bytes are released automatically upon `drain`, `drain_kv`, `discard`, `discard_kv`, and when orphan transactions are reaped by `reap_orphans` / `reap_orphans_bounded`.
```
