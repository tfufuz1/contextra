# Spec-Sync Fragment for S-01

## Section Number
§4.1 / Compaction Candidate Selection & Manifest Format

## Old Text
Size-tiered compaction groups SSTables by file size ratio without enforcing contiguous sequence bounds (`max_seq`), allowing non-contiguous SSTable selections that cause version shadowing. Manifest `Replace` entries serialize an `insertion_point` as `rank`.

## New Text
Size-tiered and fallback compaction candidate selection returns exclusively a contiguous subslice of the SSTable list sorted by `max_seq`. Before performing the in-memory swap, contiguity across input SSTables is re-validated under lock; if concurrent flushes or modifications break contiguity, compaction aborts cleanly without writing a manifest entry. Manifest `Replace` entries no longer write `rank` (serializing 0u64 for binary payload structure compatibility), and manifest recovery determines valid SSTables strictly from manifest operation order.
