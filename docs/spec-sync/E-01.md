# Spec-Sync Fragment for E-01

## Section Number
§18.4 / Tenant Collection Handle Caching & TenantPolicy Isolation Gate

## Old Text
Tenant collection instances constructed via `collection_for_tenant` or `collection_with_language_and_tenant` create un-cached `Collection` handles on every invocation, causing disjoint in-memory vector/graph indices across multiple handles of the same tenant.

## New Text
Tenant collection handles are cached in `Contextra` under `tenant_collections` (`RwLock<AHashMap<(TenantId, String), Arc<Collection<TenantScopedStorage<Arc<LsmStorage>>>>>>`). Double-Checked Locking guarantees single-instance semantics per `(TenantId, Name)` without holding locks during async index/graph storage loading. `drop_collection` and `wait_shutdown` invalidate cached handles. `TenantPolicy` (`Optional`, `Required`) in `ContextraConfig` enforces mandatory multi-tenant isolation: when `TenantPolicy::Required` is active, non-tenanted access via `collection(...)` returns `ContextraError::InvalidInput`. `TenantScopedStorage` is re-exported at `contextra_store::TenantScopedStorage`.
