# Spec-Sync Fragment for S-04

## Section Number
§15.2 / SSTable On-Disk Format v4 & MemTable Range Sharding

## Old Text
SSTable format v3 uses a fixed 256-bit Bloom filter per data block (`[u64; 4]`) and 32-bit offsets. MemTable entries are sharded across independent partitions using range-sharding over 2-byte key prefixes.

## New Text
SSTable format v4 introduces adaptive per-block Bloom filters dynamically sized per key count (10 bits per key, $k=7$, double hashing via Blake3) with a 4-byte `bloom_len` field in the block trailer (`[entries...] [bloom_bytes] [u32 offsets...] [u32 bloom_len] [u32 num_offsets]`). Format v4 achieves a false positive rate under 1.0% (measured <= 0.60%). Readers support format versions v0 through v4 with backward-compatible v3 Bloom filter semantics. `SstableBuilder` writes format v4 by default while providing additive version configuration. MemTable range-sharding deterministically maps keys to range shards via 2-byte prefix calculation (`(b0 << 8) | b1`), preserving strict key monotonicity (`keyA <= keyB => shard_for(keyA) <= shard_for(keyB)`) and enabling single-shard prefix scan pruning (`shard_range_for_prefix`).
