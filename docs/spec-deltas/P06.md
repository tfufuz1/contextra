# Specification Delta - P06 (WP-7 + WP-ST2): WAL Retire/Scope-Purge, Anchor Verification & Silent I/O Failures

## Summary
This delta documents the implementation of `wal::retire::retire_for_scope`, the `verify_wal_anchor` verification function with LSM recovery wiring, error propagation and `// INTENTIONAL-DROP` annotations for dropped `Result` values in `wal/`, and hardening of `pending_sealed_wals` cleanup in compaction and recovery.

---

## Changed / Added APIs

### Module: `contextra_store::wal::retire`
- Added `retire_for_scope`:
  ```rust
  pub async fn retire_for_scope(
      wal_dir: &Path,
      manifest: &Manifest,
      scope: &PurgeScope,
      as_of_tx: u64,
      checkpoint_tx: u64,
      key_manager: Option<Arc<KeyManager>>,
      mode: WalPurgeMode,
      scrub_policy: ScrubPolicy,
  ) -> Result<WalRetireReport>
  ```
  - Seals active segment if candidate entries match scope or checkpoint bounds.
  - Appends Manifest `WalCheckpoint{hmac}` entry and fsyncs parent directory before modifying or removing files ("ANKER ZUERST").
  - Retires fully obsolete segments using `scrub_if_safe` / `durable_remove`.
  - Re-encodes mixed segments via `purge_wal_scope` omitting scope frames and re-chaining HMAC.
  - Protects `Archived` and `Backup` file classes, returning `ContextraError::PolicyViolation` if encountered without explicit `WalPurgeMode::PurgeWithScrub` mode.

### Module: `contextra_store::wal::anchor`
- Added `verify_wal_anchor`:
  ```rust
  pub fn verify_wal_anchor(
      expected_hwm: &[u8; 32],
      actual_tail_hmac: &[u8; 32],
      replayed_hmac_set: &HashSet<[u8; 32]>,
      first_frame_prev_hmac: Option<&[u8; 32]>,
      entries_empty: bool,
  ) -> Result<AnchorCheck>
  ```
- Added `AnchorCheck` enum: `HwmInReplay`, `FirstFramePrevMatches`, `EmptyAfterRetire`.

---

## Invariants & Guarantees
1. **ANKER ZUERST**: `retire_for_scope` durably writes the Manifest `WalCheckpoint{hmac}` anchor prior to removing or modifying any WAL segment files.
2. **Scrubbing on Retire**: Obsolete WAL segments are disposed of via `scrub_if_safe` with fallback to `durable_remove` and parent directory fsync.
3. **Anchor Verification**: `verify_wal_anchor` verifies HWM alignment across replay, continuation prev HMACs, or empty states without comparing expected HWM tautologically with itself.
4. **S5 Retain Failure**: Failed sealed WAL segment removals in `LsmStorage::flush` are retained in `pending_sealed_wals` for retry in subsequent flush cycles instead of being discarded.
