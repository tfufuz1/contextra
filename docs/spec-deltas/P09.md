# Spec-Delta P09: Purge Fehlertaxonomie und Phasen-Konsolidierung

## Übersicht
Dieses Dokument beschreibt die Änderungen an der Purge-Fehlertaxonomie und der `PurgePhase`-Zustandsmaschine im Rahmen von Auftrag P09 (WP-1 + WP-2).

## Geänderte APIs und Typen

### 1. Trennung von `PurgeBlocked` und `PurgeError` (`contextra-ports/src/erasure.rs`)
- `PurgeBlocked` kapselt vorübergehende Vorbedingungen, die eine Wiederholung der Purge-Operation zulassen:
  - `ActiveSnapshot { min_seq: u64 }`
  - `CheckpointClones { copy_ids: Vec<String> }`
  - `ReaderPinned`
  - `CompactionBusy`
  - `PurgeInProgress`
  - `InsufficientDiskSpace { needed: u64, free: u64 }`
  - `UnclassifiedFiles { count: usize }`
  - `SecureDeleteUnsupported { reason: String }`
  - `UnknownFreeSpace`
- `PurgeBlocked::retry_hint()` liefert ein erschöpfendes `match` auf alle Varianten mit konkreten Handlungsempfehlungen.
- `PurgeError` kapselt unumkehrbare / harte Fehler:
  - `Blocked(#[from] PurgeBlocked)`
  - `Read { file: String, offset: u64, source_details: String }`
  - `Write { file: String, source_details: String }`
  - `Manifest(String)`
  - `Journal(String)`
  - `Fence(String)`
  - `Intent(String)`
  - `ScopeUnavailable { purge_id: PurgeId }`
  - `ScopeMismatch { purge_id: PurgeId }`
  - `ResidueFound { file: String }`
  - `DisposeRefused(String)`
  - `#[cfg(any(test, feature = "test-utils", feature = "fault-injection"))] Failpoint(&'static str)`

### 2. Entfallene Typen & verlustbehaftete Konvertierungen
- `OrxPurgeError` wurde entfernt / durch `PurgeError` ersetzt.
- Die verlustbehaftete Umwandlung `other => OrxPurgeError::Blocked(other.into())` entfällt vollständig.
- `PurgeOutcome::Failed { phase, error: PurgeError }` nutzt den neuen getypten Fehler.
- Textsuche `'Failpoint triggered:'` ist in der Produktionslogik entfallen.

### 3. Konsolidierte `PurgePhase` (`contextra-store/src/lsm/purge/plan.rs`)
- Genau EINE `PurgePhase` Enum mit `#[repr(u8)]` und abgeleitetem `Ord`:
  - `Admitted = 1`
  - `Fenced = 2`
  - `Flushed = 3`
  - `Rewriting = 4`
  - `Disposing = 5`
  - `WalRetiring = 6`
  - `Witnessing = 7`
  - `Finalizing = 8`
  - `Released = 9`
- Phase Code 0 wird nie persistiert und führt beim Lesen (`TryFrom<u8>`) zu `Err(PurgeError::Intent(...))`.
- Legacy-Phase-Codes werden fail-closed abgelehnt.
- `PurgePhase::must_run(target)` ermittelt per `self <= target`, ob die jeweilige Phase ausgeführt werden muss.
- `PurgeOrchestrator` aktualisiert `purge.intent` atomar nach erfolgreicher Ausführung der jeweiligen Phase.

## Invarianten
- **INV-ERA-1:** Jede Aussage über Purge-Fehler und -Blockaden folgt aus einem getypten Zustand (`PurgeBlocked` bzw. `PurgeError`), nie aus einem freien String.
- **Fail-Closed Resumption:** Interrumpierte Intent-Dateien werden bei der Wiederaufnahme getypt ausgewertet; Phasen vor oder bei `Rewriting` erfordern ein aktives `LsmStorage`-Handle.
