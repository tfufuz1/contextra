# Spec Delta P08 (WP-11): Restore und Anti-Resurrection (typisiert, fail-closed)

**Datum:** 2026-10-21
**Modul:** `contextra-checkpoint`, `contextra-store`, `contextra-engine`
**Referenz:** WP-11 / P08 / Spec §5.9, §5.12

## 1. Übersicht und Motivation
Vor P08 hielt `PersistentCheckpointStore` einen optionalen `Option<Arc<dyn CpyRestoreFilter>>`. Ohne expliziten Filter erlaubte dies potenziell einen Fail-Open-Zustand beim Restore, wenn nach dem Checkpoint Daten gelöscht/erased wurden.

Mit P08 wird der Restore-Pfad streng typisiert und fail-closed modelliert:
1. `Option<Arc<dyn CpyRestoreFilter>>` wurde durch `RestorePolicy` ersetzt. Ein Store ohne explizite Policy verwendet standardmäßig `RestorePolicy::ForbidAfterErasure` und verweigert die Wiederherstellung nach Folge-Transaktionen fail-closed.
2. `NoOpRestoreFilter` ist ausschließlich für Testzwecke gegatet (`#[cfg(any(test, feature = "testing"))]`).
3. `LedgerSource` (`Direct(Arc<ErasureLedger>)` vs. `Handle(Arc<ErasureLedgerHandle>)`) garantiert auf Typebene, dass ein Fail-Open-Zustand ("beide None") unrepräsentierbar ist.

---

## 2. API-Änderungen

### 2.1 `contextra-checkpoint::restore_filter::RestorePolicy`
```rust
#[derive(Clone)]
pub enum RestorePolicy {
    /// Filtere Datensätze mittels des angegebenen Anti-Resurrection-Filters.
    Filter(Arc<dyn CpyRestoreFilter>),
    /// Bietet strikten Schutz: Restore nach Löschhistorie/Folge-Transaktionen ist verboten.
    ForbidAfterErasure,
}
```

### 2.2 `PersistentCheckpointStore`
- `restore_policy`: `RestorePolicy` (Default: `ForbidAfterErasure`)
- Neue / aktualisierte Methoden:
  - `pub fn with_restore_policy(mut self, policy: RestorePolicy) -> Self`
  - `pub fn set_restore_policy(&mut self, policy: RestorePolicy)`
  - `pub fn restore_policy(&self) -> &RestorePolicy`
  - `pub fn with_restore_filter(mut self, filter: Arc<dyn CpyRestoreFilter>) -> Self`
  - `pub fn set_restore_filter(&mut self, filter: Arc<dyn CpyRestoreFilter>)`

### 2.3 `NoOpRestoreFilter`
Gegatet via `#[cfg(any(test, feature = "testing"))]` in `restore_filter.rs` und `lib.rs`.

### 2.4 `LedgerSource`
```rust
#[derive(Clone)]
pub enum LedgerSource {
    Direct(Arc<ErasureLedger>),
    Handle(Arc<ErasureLedgerHandle>),
}
```
Verwendet in `StreamingRestoreGuard` (`contextra-store`) and `DpiRestoreFilter` (`contextra-engine`).

---

## 3. Invarianten
- **Anti-Resurrection Barrier:** Ein Checkpoint-Restore ohne explizit gesetzten Anti-Resurrection-Filter bricht mit `ContextraError::Transaction` ab, sobald `last_tx > checkpoint_meta.tx_id` gilt.
- **Fail-Closed Type Safety:** Es existiert kein Konstruktor oder Repräsentation für `LedgerSource` ohne gültigen Ledger (`Direct` oder `Handle`).
