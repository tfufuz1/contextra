# Spec Delta P05 — Engine Transaction Saga-Commit & SSI Read Set Tracking (WP-E1 / WP-E2)

**Stand:** 2026-10-21
**Autor:** Principal Rust Database Engineer
**Status:** Implemented & Verified

---

## 1. Ziel & Zusammenfassung
Diese Spezifikationsänderung dokumentiert die Härtung der Transaktions- und SSI-Semantik in `contextra-engine` für Auftrag P05 (B-01 und B-02):

1. **Store-Commit als einziger Commit-Punkt (INV-IDX-1)**: Der LSM-Store-Commit ist der einzige irreversible Entscheidungspunkt der Transaktion. Folgeschritte (HNSW Vector Index, BM25 Text Index, CSR Graph) werden danach nachgezogen. Schlägt ein Folgeschritt fehl, wird die Transaktion **nicht** per Saga-Rollback auf dem LSM-Store kompensiert, sondern die Collection wird in den Gesundheitszustand `NeedsRecovery` (`mark_needs_recovery("index_followup_failed")`) versetzt. Die Transaktion bleibt committed.
2. **Kompensations- & Rollback-Fehlerbehandlung (INV-DB-3)**: Fehler bei Vor-Commit-Rollbacks werden vollständig strukturiert propagiert und protokolliert. Keine Stille-Dropping (`let _ =` auf Result-Typen ohne explizites `INTENTIONAL-DROP`).
3. **SSI ReadSet & Fail-Closed Gate (B-02 / INV-NOOP-1)**: `DbTransaction` verfolgt, ob nicht-erfassbare Leseoperationen durchgeführt wurden (`mark_untracked_read()`). Versucht eine Transaktion mit unvollständig erfassten Lesezugriffen ein SSI-Commit über `validate_ssi_gate()`, wird das Commit ehrlich mit `Err(ContextraError::CapabilityUnsupported { capability: "ssi_validation", ... })` abgelehnt (INV-NOOP-1).

## 2. Invarianten & API-Änderungen

### 2.1 Engine Transaction Commit Flow (`db_transaction_commit.rs`)
- **Phase (a)**: SSI-Gate Validierung (`validate_ssi_gate()`). Ist `has_untracked_reads()` wahr, Abbruch mit `CapabilityUnsupported`. Schreiben des initialen `CommitIntent::Pending { stages_completed: 0 }`.
- **Phase (b)**: Atomarer LSM-Store Commit (`storage.commit(tx_id)`).
  - Schlägt der Store-Commit fehl, wird ein LIFO-Rollback über das `CommitLedger` ausgeführt und der Fehler propagiert.
  - Gelingt der Store-Commit, ist die Transaktion irreversibel committed (`committed = true`).
- **Phase (c)**: Nachziehen der Indizes (Text, HNSW, Graph).
  - Tritt in dieser Phase ein Fehler auf, bleibt der LSM-Store committed. Die Collection registriert die Divergenz per `mark_needs_recovery("index_followup_failed")`.
- **Phase (d)**: Atomares Schreiben des Markers `CommitIntent::Committed`.

### 2.2 DbTransaction Read Tracking API (`db_transaction.rs`)
- `tx.mark_untracked_read()`: Registriert, dass ein un-trackbarer Lesepfad in der Transaktion verwendet wurde.
- `tx.has_untracked_reads() -> bool`: Zeigt an, ob un-trackbare Leseoperationen vorliegen.
- `tx.record_read(key, snapshot_seq)`: Registriert einen gezielten Schlüssel-Lesezugriff im `ReadSet`.
- `tx.record_prefix_read(prefix, snapshot_seq)`: Registriert einen Bereichs-Lesezugriff für Phantom-Schutz im `ReadSet`.

## 3. Out-of-Scope Findings & Patch-Skizze

### Befund: Lesezugriffe in `crates/contextra-engine/src/collection/crud/read.rs`
Standard-Leseoperationen (`Collection::get`, `scan`, `scan_prefix`, `hybrid_search`) nehmen derzeit kein `&DbTransaction` entgegen oder nutzen un-getrackte Speicher-Iteratoren.
Da `crates/contextra-engine/src/collection/crud/read.rs` außerhalb des freigegebenen Scopes liegt, wurde das SSI-Gate so gehärtet, dass untrackbare Transaktionslesepfade ehrliche `CapabilityUnsupported`-Fehler auslösen.

### Patch-Skizze für Folgeauftrag (`engine/collection/crud/read.rs`)
```rust
// In crates/contextra-engine/src/collection/crud/read.rs

impl<S: StorageEngine, V: VectorIndex> Collection<S, V> {
    /// Ergonomie-Wrapper für get() innerhalb einer Transaktion mit SSI ReadSet Tracking.
    pub async fn get_tx(&self, tx: &DbTransaction<S, V>, id: &str) -> Result<Option<StoredDocument>> {
        let key = self.namespaced_key(id.as_bytes(), 0);
        let seq = self.snapshot_seq().await?;
        tx.record_read(&key, seq);
        self.get(id).await
    }

    /// Ergonomie-Wrapper für scan_prefix() innerhalb einer Transaktion mit SSI ReadSet Tracking.
    pub async fn scan_prefix_tx(
        &self,
        tx: &DbTransaction<S, V>,
        prefix: &str,
        limit: Option<usize>,
    ) -> Result<Vec<(String, serde_json::Value)>> {
        let real_prefix = self.namespaced_key(prefix.as_bytes(), 0);
        let seq = self.snapshot_seq().await?;
        tx.record_prefix_read(&real_prefix, seq);
        self.scan_prefix(prefix, limit).await
    }
}
```

## 4. Test-Abdeckung
Folgende Tests in `crates/contextra-engine/tests/transaction_saga_ssi_tests.rs` belegen die Funktionsfähigkeit:
- `tx_no_intermediate_state_visible_to_readers`: Leser sehen keine uncommitteten Zwischenzustände.
- `tx_rollback_error_is_propagated`: Fehler bei Kompensation/Rollback werden propagiert.
- `tx_followup_failure_marks_index_diverged_but_commit_stands`: Store-Commit steht trotz Index-Followup-Fehler; Collection wird als divergiert markiert.
- `tx_crash_recovery_commit_intent_idempotent`: Crash-Recovery von `CommitIntent` verhält sich deterministisch und idempotent.
- `ssi_detects_write_skew_via_scan`: Un-getrackte Lesezugriffe führen unter SSI fail-closed zu `Err(CapabilityUnsupported)`.
