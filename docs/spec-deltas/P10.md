# Spec Delta P10 (WP-6): Fence-Protokoll Vollendung

## Status
Approved & Implemented

## Summary of Changes
1. **Dekker / SeqCst Memory Ordering**:
   - `ErasureGate::is_active`, `ErasureGate::inflight_count`, `ErasureGate::inc_inflight`, `ErasureGate::dec_inflight`, and drain loop checks now strictly execute with `Ordering::SeqCst`.
   - Every atomic operation in `fence.rs` has been annotated with `// ORDERING: <Begründung>` explaining its role in the Dekker mutual exclusion guarantee.

2. **Group-Commit Path (`write.rs`)**:
   - Leader and Follower index operations are aggregated under `commit_lock`.
   - `enter_write` is acquired for all keys in the batch before WAL append.
   - `WriteTicket` is held until after memtable updates are published, eliminating the Check-Then-Act window (N8).
   - On Leader cancellation or failure, `LeaderCancelGuard` ensures `WriteTicket` and intent locks are cleaned up without leaking `inflight` counters.

3. **Drain Protocol without Polling**:
   - `acquire_fence` uses `tokio::pin!(notified); notified.as_mut().enable();` prior to checking `inflight == 0`, preventing lost wakeups.
   - Removed 2ms polling loop in favour of async notification with timeout.
   - Timeout during fence acquisition returns `Err(FenceError::DrainTimeout)` and releases installed fences.

4. **Exhaustive Matching on IndexOp (`fenced_keys`)**:
   - Added `fenced_keys` and `fenced_keys_kv` helper functions using exhaustive variant matching on `IndexOp`.
   - `IndexOp::Delete { data: None }` is evaluated as `FencedKey::Unknown` and rejected when a fence is active.

5. **Invariants & Errors**:
   - `FenceError` extended with `DrainTimeout` and `ScopeFenced`.
   - `PrefixFence` now wraps `PurgeScope` (distinguishing exact keys and prefixes).
