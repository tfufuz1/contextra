# SPEC DELTA P03 (WP-S4): MCP Tool List, Windows IPC, Hardening

## Summary
This spec delta documents changes to the MCP tool list registration, Windows IPC fail-closed behavior, and process hardening error handling introduced in Auftag P03.

## Modified APIs & Invariants

### 1. Dynamic Tool List Registration (`contextra-mcp`)
- **Finding Ref:** F-06, F-27
- **Invariants:**
  - The MCP tool list (`tools/list` and dispatch handlers) is dynamically constructed based on active registered modules, sandbox policies, and features rather than a static list constant.
  - `contextra_cloud_query` is excluded in default EP1 builds when cloud egress is not permitted or when feature `guard` is absent.
  - Optional tools (`contextra_plugin_status`, `contextra_relate`, `contextra_relate_n_ary`) are included only when their corresponding module or policy permission (e.g. `plugin_registry` or `allow_db_writes`) is active.

### 2. Windows IPC Fail-Closed Enforcement (`contextra-mcp`)
- **Finding Ref:** B-08, F-20
- **Invariants:**
  - `peer_cred.rs` is strictly compiled for Unix targets (`#[cfg(unix)]`).
  - `run_windows_listener` in `IpcServer` no longer logs fake success messages or returns `Ok(())`. It strictly returns `Err(ContextraError::Unsupported("Windows Named Pipe IPC listener is unsupported"))`.
  - Windows IPC proxy runner in `IpcProxy` fails closed with `ContextraError::Unsupported`.

### 3. Process Hardening Startup Error (`contextra-sys`)
- **Finding Ref:** INV-NOOP-1
- **Invariants:**
  - On non-Linux platforms where process hardening cannot be applied natively, `harden_process()` fails closed with `std::io::ErrorKind::Unsupported` instead of returning a silent no-op success report.
  - All `unsafe` blocks in `contextra-sys` (`hardening.rs`, `acl_win32.rs`) are annotated with explicit `// SAFETY:` comments.

## Test Verification

- `ep1_build_has_no_cloud_tool`: Verifies that `contextra_cloud_query` is absent from `tools/list` and rejected on dispatch in default EP1 builds.
- `tool_list_derived_from_registry`: Verifies that `tools/list` dynamically updates based on plugin registry and sandbox write permissions.
- `windows_ipc_unsupported_returns_err`: Verifies that Windows IPC listener invocations return `ContextraError::Unsupported`.
- `hardening_unsupported_is_startup_error`: Verifies that process hardening on unsupported target platforms returns `ErrorKind::Unsupported`.
