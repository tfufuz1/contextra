## 4. Befunde

### Befund J-19-F01: Pytest drop_collection entfernt Collection nicht aus list_collections
- **Schwere:** S2 (Integritäts-/Korrektheitsfehler)
- **Datei:Zeile:** `crates/contextra-py/tests/test_bindings.py:77` [BELEGT]
- **Beweisstufe:** [GEMESSEN]
- **Erwartet:** `db.drop_collection("col1")` entfernt die Collection, sodass `"col1" not in db.list_collections()` gilt.
- **Tatsächlich:** `list_collections()` gibt weiterhin `['col1', 'col2', 'default']` zurück, Test schlägt fehl mit `AssertionError`.
- **Ein-Zeilen-Reproduktion:**
  `VIRTUAL_ENV=/tmp/venv PATH="/tmp/venv/bin:$PATH" /tmp/venv/bin/pytest crates/contextra-py/tests/test_bindings.py -k test_collection_management`
- **Geschwister-Fundstellen (R7):** `crates/contextra-py/src/bindings/db.rs:120` (`drop_collection` delegiert an `self.inner.drop_collection`).
- **Fix-Skizze:** In `crates/contextra-py/src/bindings/db.rs` bzw. im zugrundeliegenden Database-Collection-Manager sicherstellen, dass die Metadata/Collection-Registrierung beim Drop synchron aktualisiert oder gecleared wird.

---

### Befund J-19-F02: String-Mismatches in Python Exception Error Message Validation
- **Schwere:** S4 (Kosmetischer/Test-Validierungsfehler)
- **Datei:Zeile:** `crates/contextra-py/tests/test_errors.py:173` [BELEGT]
- **Beweisstufe:** [GEMESSEN]
- **Erwartet:** Python Exception String enthält `"exceeds maximum length of 64 bytes"`.
- **Tatsächlich:** Exception String lautet `"Collection name too long (max 64)"`.
- **Ein-Zeilen-Reproduktion:**
  `VIRTUAL_ENV=/tmp/venv PATH="/tmp/venv/bin:$PATH" /tmp/venv/bin/pytest crates/contextra-py/tests/test_errors.py -k test_long_collection_name_validation`
- **Geschwister-Fundstellen (R7):** `crates/contextra-py/src/bindings/common.rs:94` (`validate_collection_name`).
- **Fix-Skizze:** Fehlermeldung in `crates/contextra-py/src/bindings/common.rs` an den in den Python-Tests erwarteten Text anpassen oder Python-Teststring aktualisieren.

---

### Befund J-19-F03: Exception-Typ Mismatch bei leerer Document ID in put_kv
- **Schwere:** S3 (Robustheits-/Wahrheitslücke in API-Garantie)
- **Datei:Zeile:** `crates/contextra-py/tests/test_kv_links.py:136` [BELEGT]
- **Beweisstufe:** [GEMESSEN]
- **Erwartet:** `with pytest.raises(ValueError)` fängt Fehler bei leerer ID ab.
- **Tatsächlich:** `col.put_kv("", ...)` wirft `_contextra.ContextraValueError`, welches von pytest nicht als Standard-Python-`ValueError` gefangen wird.
- **Ein-Zeilen-Reproduktion:**
  `VIRTUAL_ENV=/tmp/venv PATH="/tmp/venv/bin:$PATH" /tmp/venv/bin/pytest crates/contextra-py/tests/test_kv_links.py -k test_invalid_and_empty_id`
- **Geschwister-Fundstellen (R7):** `crates/contextra-py/src/bindings/common.rs` (Definition von `ContextraValueError`).
- **Fix-Skizze:** `ContextraValueError` in `crates/contextra-py/src/bindings/common.rs` als Unterklasse von `PyValueError` / `PyException` registrieren oder Test in Python auf `ContextraValueError` umstellen.
