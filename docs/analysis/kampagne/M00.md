## 4. Detaillierte Prüfung der konkreten Fragestellungen (a)–(f)

### a) W0-01: WAL-Größenaktualisierung bei Truncate [BELEGT]
- **Befund:** In `crates/contextra-store/src/wal/flusher.rs:444` wird die atomare Variable `size` **vor** dem Aufruf von `file.set_len(offset).await` und `file.sync_all().await` aktualisiert:
  ```rust
  // flusher.rs Line 444
  size.store(offset, std::sync::atomic::Ordering::SeqCst);
  if let Err(e) = file.set_len(offset).await { ... }
  ```
- **Folge:** Schlägt `set_len` oder `sync_all` fehl, zeigt `size` bereits die reduzierte Länge an, während die Datei auf der Festplatte noch ungekürzt ist (TOCTOU / State-Desynchronisation).
- **Beleg:** `crates/contextra-store/src/wal/flusher.rs:444` [BELEGT].

## 6. Priorisierte Top-5-Lückenliste für nachfolgende Aufträge

1. **[Prio 1] W0-13 / W0-12: `--all-features` Kompilierbarkeit & `DocId` 128-Bit Konsistenz**
   - *Problem:* `cargo check --tests --all-features -p contextra-vector` schlägt fehl (`DocId::new` erwartet `u128`).
   - *Aktion:* `DocIdRaw` und Testhelfer in `contextra-vector` und `contextra-text` durchgehend für `u128` anpassen, wenn `docid-128` aktiv ist.

2. **[Prio 2] W0-01: WAL Truncate Atomarität im Flusher (TOCTOU)**
   - *Problem:* `size.store(offset)` wird vor `file.set_len(offset)` ausgeführt.
   - *Aktion:* `size.store(offset)` erst **nach** erfolgreichem `file.set_len(offset)` und `file.sync_all()` ausführen.

3. **[Prio 3] W0-03: Transaktions-Intent Recovery & Orphan Worker Anbindung**
   - *Problem:* `recover_pending_intents` ist ungenutzt; orphan cleanup worker wird beim Engine-Start nicht gestartet.
   - *Aktion:* Background-Worker in `contextra_impl/lifecycle.rs` bei Engine-Open starten und `recover_pending_intents` an den Recovery-Pfad koppeln.

4. **[Prio 4] W0-08 / W0-09: End-to-End RevocationLog Anbindung & Memory Purge**
   - *Problem:* Geöffnete `RevocationLog`-Instanz wird beim Starten der Engine nicht an `KvSegmentCipher` und `KeyRegistry` übergeben.
   - *Aktion:* In `contextra-engine/src/contextra_impl/lifecycle.rs` das `RevocationLog` verdrahten und `purge_tenant_segments` bei Revokation ausführen.

5. **[Prio 5] W0-07: AuditChain Anchor-Verifikation in Checkpoint/Recovery integrieren**
   - *Problem:* `verify_chain_against_anchor` sichert die Audit-Kette gegen History-Forking, wird aber im Engine-Betrieb nie aufgerufen.
   - *Aktion:* Anker-Prüfung in `CheckpointManager` und beim Start der Engine erzwingen.
