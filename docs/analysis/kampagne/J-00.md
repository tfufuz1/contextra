# Umgebungs-Baseline und Abhängigkeits-Lückenbericht (J-00)

## 1. Zusammenfassung

Das Gesamtsystem und die VM-Umgebung für Contextra wurden in Schritt 1 bis 4 umfassend analysiert, verifiziert und ergänzt.
- **Toolchain & Werkzeuge**: **GRÜN** — Toolchain hart gepinnt auf Rust 1.89.0 (`29483883e 2025-08-04`). Alle Basistools (Cargo, Clippy, rustfmt) sowie Ergänzungstools (`just`, `ast-grep`, `cargo-deny`, `cargo-audit`, `cargo-llvm-cov`, `cargo-mutants`, `cargo-fuzz`) sind nach der Ausführung voll einsatzbereit.
- **Netzwerk-Konnektivität**: **GRÜN** — Alle 8 geforderten Hosts (crates.io, github, nixos, pypi, huggingface) sind direkt per HTTP/HTTPS erreichbar.
- **Repository-Gesundheit**: **GELB** — Der Workspace kompiliert und `cargo fetch --locked` verläuft fehlerfrei. Es bestehen jedoch geringfügige Abweichungen im HEAD-Commit-Stand (`6c8e8e40` statt Referenz `e5bbb44d`/`a172c13`), der Crate-Zählung (33 Crates in `capabilities.toml`, 35 Workspace-Member inkl. `contextra-bench` und `xtask`) sowie bei Unsafe-Insel-Spezifikationen.
- **Umgebungswerkzeuge & Fehlen**: **GELB** — `flatc` wurde via `apt-get` installiert; `cargo-llvm-cov`, `cargo-mutants` und `cargo-fuzz` (v0.12.0) wurden nachinstalliert. `libonnxruntime` fehlt im Linker-Cache (relevant für J-19).

**Reifegrad-Einschätzung (R0–R4)**:
- **R3 (Produktionsreif mit Evidenz)** für Toolchain-Prüfung, Build-Fähigkeit und Basis-Infrastruktur.
- **R1 (Happy Path)** für ONNX-Inferenz / native Bibliotheken (aufgrund fehlender `libonnxruntime` im System-Linker-Cache).

## 4. Befunde

### J-00-F01: Commit-Drift gegenüber Referenzstand e5bbb44d / a172c13
- **Schwere**: S4 (Kosmetisch / Verfolgbarkeit)
- **Datei:Zeile**: Git Repository State (HEAD)
- **Beweisstufe**: [GEMESSEN]
- **Erwartet**: HEAD auf `e5bbb44d` (Vor-Analyse) bzw. `a172c13` (Quellcode-Abgleich Stand).
- **Tatsächlich**: HEAD steht bei `6c8e8e406434435700d60f6a3d01ca4468ce066b` ("docs(kampagne): add J-01 gate matrix diagnostic report (#4131)").
- **Ein-Zeilen-Reproduktionsbefehl**: `git rev-parse HEAD`
- **Geschwister-Fundstellen (R7)**: N/A
- **Fix-Skizze**: Abweichungen in Berichten transparent dokumentieren und auf aktuellem Stand `6c8e8e40` arbeiten.

### J-00-F02: Spezifikations- und Code-Widerspruch bzgl. Unsafe-Insel `contextra-vector/src/distance.rs`
- **Schwere**: S3 (Dokumentations- / Wahrheitslücke)
- **Datei:Zeile**: `capabilities.toml:1-120`, `AGENTS.md:50`, `xtask/src/gates/debt_audit.rs:25`, `crates/contextra-vector/src/distance.rs:1`
- **Beweisstufe**: [BELEGT]
- **Erwartet**: Konsistente Deklaration aller Unsafe-Inseln über Workspace-Dateien hinweg.
- **Tatsächlich**:
  1. `capabilities.toml` führt `unsafe_island = true` nur für `contextra-simd`, `contextra-sys`, `contextra-wire`.
  2. `AGENTS.md` führt zusätzlich `contextra-vector/src/distance.rs` als Unsafe-Insel auf.
  3. `xtask/src/gates/debt_audit.rs` erlaubt explizit `crates/contextra-vector/src/distance.rs` als Unsafe-Ausnahme.
  4. Quellcode `crates/contextra-vector/src/distance.rs:1` enthält explizit: `// INVARIANTEN: Zero unsafe code in distance.rs; Delegierung an contextra-simd.`. Es enthält 0 `unsafe`-Blöcke.
- **Ein-Zeilen-Reproduktionsbefehl**: `rg "unsafe" crates/contextra-vector/src/distance.rs`
- **Geschwister-Fundstellen (R7)**: `capabilities.toml`, `AGENTS.md`, `xtask/src/gates/debt_audit.rs`
- **Fix-Skizze**: Angleichung der Dokumentation (`AGENTS.md` und `xtask/src/gates/debt_audit.rs`) an den tatsächlichen Code-Zustand (reines Safe Rust in `distance.rs`) bzw. Aktualisierung der `capabilities.toml`.

### J-00-F03: Inkonsistente Crate-Zählung zwischen Prompt, capabilities.toml und Cargo.toml
- **Schwere**: S4 (Inkonsistenz)
- **Datei:Zeile**: `capabilities.toml:1`, `Cargo.toml:workspace.members`
- **Beweisstufe**: [GEMESSEN] / [BELEGT]
- **Erwartet**: Einheitliche Mengenangabe aller Crates im Repository.
- **Tatsächlich**:
  - Prompt bezeichnet Workspace als "32 Crates + xtask".
  - `capabilities.toml` registriert genau 33 Crates (31 `contextra-*`, `contextra`, `contextra-testkit`).
  - `cargo metadata` zählt 35 Workspace-Package-Members (33 Crates + `benchmarks/contextra-bench` + `xtask`).
- **Ein-Zeilen-Reproduktionsbefehl**: `python3 -c "import json; m=json.load(open('/tmp/J-00/metadata.json')); print(len(m['workspace_members']))"`
- **Geschwister-Fundstellen (R7)**: `capabilities.toml`, `Cargo.toml`
- **Fix-Skizze**: Dokumentation und Inventare auf 33 Fach-Crates + 1 Benchmark-Crate + 1 Tooling-Crate (xtask) = 35 Workspace-Members festlegen.

### J-00-F04: MSRV-Konflikt bei neuester `cargo-fuzz` Version v0.13.2 mit Rust 1.89.0
- **Schwere**: S3 (Werkzeugkompatibilität)
- **Datei:Zeile**: Cargo Install Registry (`cargo-platform v0.3.3`)
- **Beweisstufe**: [GEMESSEN]
- **Erwartet**: `cargo install cargo-fuzz` baut unkompliziert mit der gepinnten Toolchain 1.89.0.
- **Tatsächlich**: `cargo install cargo-fuzz --locked` wählt v0.13.2, was indirekt über `cargo-platform v0.3.3` Rust 1.91 erfordert und abbricht.
- **Ein-Zeilen-Reproduktionsbefehl**: `cargo install cargo-fuzz --locked`
- **Geschwister-Fundstellen (R7)**: N/A
- **Fix-Skizze**: `cargo install cargo-fuzz --version 0.12.0` verwenden, da v0.12.0 vollständig zu Rust 1.89.0 kompatibel ist.
