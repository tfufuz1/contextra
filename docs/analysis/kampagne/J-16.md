## 4. Befunde

### Befund J-16-F01: Abweichung zum Referenzstand e5bbb44d — WAL Sequence Gap in `open_heal_tests.rs`
- **Schwere**: S2 (Korrektheits-/Integritätsfehler)
- **Datei:Zeile**: `crates/contextra-store/src/wal/open_heal_tests.rs:48` [BELEGT]
- **Beweisstufe**: [GEMESSEN]
- **Erwartet vs. Tatsächlich**: Erwartet wird, dass `Wal::open` nach einer Abschneidung (Torn Tail) beim Anhängen neuer Einträge die sequenzielle Monotonie (`seq_no == last_seq + 1`) beibehält. Tatsächlich schlug der Reopen-Test fehl mit `WalCorruption { offset: 218, reason: "Sequence gap detected: expected 3, got 4" }`, weil im Test nach Truncation von Eintrag 3 manuell `seq_no = 4` statt `3` übergeben wurde.
- **Ein-Zeilen-Reproduktionsbefehl**: `cargo test --lib -p contextra-store -- wal::open_heal_tests`
- **Geschwister-Fundstellen**: `crates/contextra-store/src/wal/open_heal_tests.rs:135` (`test_open_heal_encrypted_wal`)
- **Fix-Skizze**: In `open_heal_tests.rs` nach Truncation den Folgeschritt mit `seq_no = 3` (bzw. `wal.last_seq_no() + 1`) vorbereiten. (Kein Produktionscode-Eingriff).

### Befund J-16-F02: Abweichung zum Referenzstand e5bbb44d — TOCTOU Panik in `test_truncate_size_visible_atomically_with_file_state`
- **Schwere**: S3 (Robustheits- / Wahrheitslücke)
- **Datei:Zeile**: `crates/contextra-store/src/wal/tests/io_tests.rs:196` [BELEGT]
- **Beweisstufe**: [GEMESSEN]
- **Erwartet vs. Tatsächlich**: Erwartet wird atomare Sichtbarkeit der Dateigröße. Tatsächlich schlägt der Test unter parallelem Threading fehl mit `panicked at poller panicked: JoinError::Panic(..., "TOCTOU violation: in-memory WAL size (246) > physical disk size (4)")`.
- **Ein-Zeilen-Reproduktionsbefehl**: `cargo test --lib -p contextra-store -- wal::tests::io_tests::test_truncate_size_visible_atomically_with_file_state`
- **Geschwister-Fundstellen**: Keine weiteren Instanzen in `io_tests.rs`.
- **Fix-Skizze**: Synchronisation der Dateigrößen-Metadaten im IO-Handle anpassen, um die Sichtbarkeits-Lücke zu schließen.

### Befund J-16-F03: Scheinabdeckung (Assertion-lose Aufrufe in Bestandstests)
- **Schwere**: S3 (Robustheits- / Wahrheitslücke)
- **Datei:Zeile**: `crates/contextra-ports/src/rng.rs:45`, `crates/contextra-types/src/model_fingerprint.rs:18` [BELEGT]
- **Beweisstufe**: [BELEGT]
- **Erwartet vs. Tatsächlich**: Aufrufe in Setup-Hilfsfunktionen erzeugen Code-Zeilen-Abdeckung, ohne dass die Rückgabewerte (z. B. Entropie-Verteilung oder Fingerprint-Stringformat) durch Assertions geprüft werden.
- **Ein-Zeilen-Reproduktionsbefehl**: `cargo test -p contextra-types`
- **Fix-Skizze**: Ergänzung von expliziten Eigenschafts-Assertions in den bestehenden Tests.
