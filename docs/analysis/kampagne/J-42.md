## 4. Befunde

### J-42-F01: Unvollständige SSI ReadSet-Verdrahtung im LSM-Lesepfad (`INV-MVCC-SSI-1`)
* **Schwere:** S2 (Korrektheits-/Integritätsfehler)
* **Datei:Zeile:** `crates/contextra-store/src/lsm/ops/read.rs:30-65`
* **Beweisstufe:** [BELEGT]
* **Erwartet:** Bei transaktionalen Lesezugriffen (`get()`, `scan()`) müssen gelesene Schlüssel deterministisch im `ReadSet` des `TxBuffer` registriert werden, um Write-Skew-Konflikte im `SequenceLogSsiValidator` zu erkennen.
* **Tatsächlich:** Standard-`get()` und `scan_prefix()` registrieren gelesene Schlüssel NICHT im `ReadSet`. Nur `get_at_seq_tracked()` tut dies. Zudem bietet `scan_prefix_tracked()` laut Quelltextkommentar keine Phantom-Protection für Bereichsabfragen.
* **Ein-Zeilen-Reproduktionsbefehl:** `cargo test -p contextra-mvcc --test campaign_j42_ssi`
* **Geschwister-Fundstellen (R7):** `crates/contextra-store/src/lsm/ops/write.rs:249`, `crates/contextra-mvcc/src/ssi.rs:761`
* **Fix-Skizze:** Alle transaktionalen Leseoperationen in `contextra-store` auf `_tracked`-Varianten umstellen und `ReadSet`-Registrierung erzwingen.

### J-42-F02: Marketing-Aussage „Zero-Panic verifiziert“ widerspricht 780 Ratchet-Panics
* **Schwere:** S3 (Robustheits-/Wahrheitslücke)
* **Datei:Zeile:** `.github/unwrap_baseline.txt:1`
* **Beweisstufe:** [GEMESSEN]
* **Erwartet:** Wenn Marketing/README „Zero-Panic-Garantie im Produktionspfad“ zusagt, dürfen keine `unwrap()`, `expect()` oder `panic!()`-Aufrufe im Produktionscode existieren.
* **Tatsächlich:** Das Ratchet-Informatik-Tool misst aktuell 780 verbliebene Panic-Stellen in den Quelltexten der Workspace-Crates (z. B. `contextra-engine`, `contextra-mcp`, `contextra-graph`).
* **Ein-Zeilen-Reproduktionsbefehl:** `cargo xtask panic-inventory --exclude-tests`
* **Geschwister-Fundstellen (R7):** `.github/workflows/unwrap-baseline-check.yml`, `docs/gates/unwrap-ratchet-removal-status.md`
* **Fix-Skizze:** README-Aussage präzisieren: „Zero-Panic in gehärteten Ring-0 Hot-Paths (über Ratchet schrittweise reduziert)“.

### J-42-F03: Widerspruch zwischen Spezifikation ("Row-Level Locks") und Code (OCC + Shard Locks)
* **Schwere:** S3 (Wahrheitslücke / Spezifikationsdrift)
* **Datei:Zeile:** `docs/spec/CONTEXTRA_FINALE_PRODUKTSPEZIFIKATION.md:1200`, `crates/contextra-mvcc/src/ssi.rs:164`
* **Beweisstufe:** [BELEGT]
* **Erwartet:** Spezifikation und Feature-Katalog dokumentieren exakt die im Code verwendete Nebenläufigkeitssteuerung.
* **Tatsächlich:** Die Spezifikation spricht von zeilenbasierten Sperren ("Row-Level Locks"). Der Code verwendet Optimistic Concurrency Control (OCC) mit nachträglicher Validierung (`SequenceLogSsiValidator`) und grobkörnigen Shard-Locks (`KvKeyLocks`).
* **Ein-Zeilen-Reproduktionsbefehl:** `rg -n "sorted_unique_shards" crates/contextra-engine/src/collection/kv_lock.rs`
* **Geschwister-Fundstellen (R7):** `crates/contextra-store/src/lsm/commit.rs`
* **Fix-Skizze:** Spezifikationstext auf „Optimistic Concurrency Control (OCC) mit ReadSet-Validierung und Shard-Level Intent Locks“ korrigieren.

### J-42-F04: Unerreichbare Skalierungsaussage „Milliarden Vektoren“ ohne In-Memory-Gigabyte/TB-RAM
* **Schwere:** S3 (Wahrheitslücke / Irreführung)
* **Datei:Zeile:** `README.md:12`, `crates/contextra-vector/src/hnsw/`
* **Beweisstufe:** [GEMESSEN]
* **Erwartet:** Skalierungsversprechen spiegeln die physische Speicherarchitektur wider.
* **Tatsächlich:** Ein HNSW-Graph mit 768d f32 Vektoren belegt ~3,4 KB pro Knoten im Arbeitsspeicher. Für 1 Milliarde Vektoren werden ca. 3,4 Terabyte RAM benötigt. Da DiskANN-Festplatten-Paging noch im Stufenmodell (ADR-083) liegt, ist das Versprechen auf Standard-Systemen schlicht unmöglich.
* **Ein-Zeilen-Reproduktionsbefehl:** `cargo bench -p contextra-vector --bench hnsw_bench`
* **Geschwister-Fundstellen (R7):** `docs/decisions/ADR-083-hnsw-diskann-stufenmodell.md`
* **Fix-Skizze:** README anpassen: „Millionen Vektoren im Arbeitsspeicher (skalierbar je nach RAM-Ausstattung)“.

### J-42-F05: Fünf schlagende `xtask` Dokumentations- und Integritäts-Gates
* **Schwere:** S3 (Dokumentations-Integritätsmangel)
* **Datei:Zeile:** `docs/spec/CONTEXTRA_FINALE_PRODUKTSPEZIFIKATION.md:3761`, `docs/SOURCE_OF_TRUTH.md:1`

* **Geschwister-Fundstellen (R7):** `cargo xtask check-doc-references`, `cargo xtask check-toc-integrity`, `cargo xtask check-crate-references`
* **Fix-Skizze:** Synchronisation mittels `cargo xtask sync-docs` ausführen und veraltete Pfad-/Crate-Referenzen in der Finale Spezifikation aufräumen.
