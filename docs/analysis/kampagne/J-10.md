## 4. Befunde

### J-10-F01: [GEMESSEN] [BELEGT] Unsafe-Block-Fehlstellen in generiertem FlatBuffers Code (`contextra-wire`)
- **Schwere:** **S2 (Korrektheits-/Integritätsfehler / Blockierender Kompilierfehler)**
- **Datei:Zeile:** `crates/contextra-wire/src/contextra_generated.rs:326, 330, 334, 448, 452, 456, 566, 660, 756, 760, 880, 884, 888, 892, 896, 900, 904, 908, 912, 916` (und 15 weitere Vorkommen).
- **Beweisstufe:** [GEMESSEN] (`cargo check -p contextra-wire --locked` liefert `error[E0133]: call to unsafe function Table::get is unsafe and requires unsafe function or block`), [BELEGT] (Quellcode in `contextra_generated.rs`).
- **Erwartet:** FlatBuffers-generierte Methoden rufen `Table::get` innerhalb eines `unsafe { ... }` Blocks auf oder die Methode ist als `unsafe fn` deklariert.
- **Tatsächlich:** Die Methode `Table::get` in Crate `flatbuffers 25.2.10` ist als `unsafe fn` markiert. Die in `contextra_generated.rs` generierten Wrapper-Getter-Methoden enthalten keinen `unsafe`-Block um `self._tab.get(...)`, was unter Rust 1.89.0 zu 35 eklatanten Kompilierfehlern führt.
- **Ein-Zeilen-Reproduktionsbefehl:**
  ```bash
  cargo check -p contextra-wire --locked
  ```
- **Geschwister-Fundstellen (R7):** Alle indirekten Abhängigkeiten in Ring 0, die `contextra-wire` importieren (`contextra-core`, `contextra-simd`, `contextra-graph`, `contextra-vector`).
- **Fix-Skizze:** Das FlatBuffers Schema (`flatc`) muss mit einer `flatc`-Version neu generiert werden, die `unsafe { self._tab.get(...) }` erzeugt, ODER in `contextra_generated.rs` müssen die Aufrufe manuell/per XTask in `unsafe { ... }` Blöcke gekapselt werden.

---

### J-10-F02: [GEMESSEN] [BELEGT] Flaky Performancetest unter Systemlast (`contextra-text`)
- **Schwere:** **S2 (Flaky-Test in CI / Falsch-Positives Testversagen)**
- **Datei:Zeile:** `crates/contextra-text/src/inverted/tests/search_tests.rs:730` (`test_high_frequency_term_resident_index_performance`).
- **Beweisstufe:** [GEMESSEN] (In Run 1 & 2 bestanden mit speedup ~2.5x, in Run 3 fehlgeschlagen mit speedup = 1.16x unter Schwellenwert 1.20x).
- **Erwartet:** Deterministische Bestätigung der Invariante IP-10a ohne Abhängigkeit von paralleler CPU-Spitzenlast auf der Test-VM.
- **Tatsächlich:** Assertion `assert!(speedup_factor >= 1.2)` misst Wanduhrzeit (`Instant::now()`) für 10.000 Dokumenten-Scans. Wenn Hintergrundprozesse oder parallele Testthreads die CPU verlangsamen, sinkt der gemessene Speedup-Faktor unter 1.2x.
- **Ein-Zeilen-Reproduktionsbefehl:**
  ```bash
  cargo test -p contextra-text --lib inverted::tests::search_tests::test_high_frequency_term_resident_index_performance
  ```
- **Geschwister-Fundstellen (R7):** `crates/contextra-text/tests/alloc_profiler.rs:238` (ebenfalls wanduhrzeitbasiert, jedoch als `#[ignore]` markiert).
- **Fix-Skizze:** Invarianten-Prüfung entkoppeln: Entweder den Test mit `#[cfg_attr(not(feature = "bench-strict"), ignore)]` versehen, oder die Anzahl abgeschnittener/vermiedener I/O- und Deserialisierungs-Operationen (Operation Counter via `MetricObserver`) anstelle roher Nanosekunden-Wanduhrzeit vergleichen.

- **Schwere:** **S3 (Wahrheitslücke in Test-Suite)**

- **Erwartet:** Gemäß Richtlinien muss jeder `#[ignore]` Test einen expliziten Grund tragen (z. B. `#[ignore = "Benchmark-Profilierung > 10s"]`).
- **Tatsächlich:** Beide Tests tragen ein amnesitisches `#[ignore]` ohne Begründung oder Ticket-ID. Bei Ausführung mit `-- --ignored` laufen sie jedoch in < 1 Sekunde erfolgreich durch.
- **Fix-Skizze:** Begründungs-String an `#[ignore = "Manuelle Profilierungs-Harness für 10k-Dokumente"]` anfügen.
