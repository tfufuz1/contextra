# J-11 Kampagnenbericht: Cargo-Feature & Kombinationen-Matrix Audit

## 1. Zusammenfassung

Das systematische Audit aller Cargo-Features, Einzel-Builds, Kombinationen und `--all-features`-Konfigurationen im Contextra-Workspace zeigt ein gemischtes Bild aus hoher Stabilität der Fassade (Ring 4) und kritischen Typ-Inkompatibilitäten bei Feature-Aktivierung in tiefen Ringen (Ring 0/1/3).
Die Fassade `contextra` schließt default-seitig `["fast", "candle"]` ein (Abweichung zur Ur-Spezifikation) und lässt sich in allen 24 getesteten Kombinations-Matrix-Pfaden (`{fast, sovereign, compliance} x {candle, ollama, onnx, none} x {router on/off}`) fehlerfrei ohne Warnungen kompilieren.
Allerdings führen `--all-features`-Aufrufe in mehrere Typfehler (E0308, E0277), wenn das Feature `docid-128` aktiviert wird, da nachgelagerte Crates (`contextra-vector`, `contextra-graph`, `contextra-engine`, `contextra-py`) nicht durchgängig von `u64` auf `u128` konvertieren bzw. `EntityId(u64)` voraussetzen.

- **Ring 0 (`contextra-types`, `-ports`, `-simd`, `-sys`, `-wire`, `-mvcc`, `-rank`, `-text`):** **R3** (Produktionsreif für 64-Bit DocId; **R1** bei `docid-128`).
- **Ring 1 (`contextra-store`, `-checkpoint`, `-kvcache`):** **R3** (Stabile Core-Features; `--all-features` Clippy-Lints in Tests).
- **Ring 2 (`contextra-infer-candle`, `-ollama`, `-onnx`, `-sandbox`):** **R2** (Candle/Ollama lauffähig; CUDA benötigt GPU-Setup).
- **Ring 3 (`contextra-db`, `-engine`, `-router`, `-cognition`, `-privacy`, `-agent`):** **R2** (`docid-128` Inkompatibilität in Engine/DB).
- **Ring 4 (`contextra`, `-mcp`, `-license`, `-py`):** **R3** (Fassade & MCP stabil; PyO3 bricht bei `docid-128`).

## 4. Befunde

### J-11-F01 (S2): Typ-Bruch bei `docid-128` in Vector Test-Suites
- **Schwere:** S2 (Korrektheits-/Integritätsfehler)
- **Datei:Zeile:** `crates/contextra-vector/tests/filtered_selectivity_recall.rs:90`, `crates/contextra-vector/tests/sq8_rerank_recall.rs:98`, `crates/contextra-vector/tests/k02_snapshot_rebuild_determinism.rs:59`
- **Beweisstufe:** [GEMESSEN]
- **Erwartet:** `cargo check -p contextra-vector --all-features --tests` kompiliert ohne Typfehler.
- **Tatsächlich:** Fehler `E0308: expected u128, found u64` beim Aufruf von `DocId::new(i as u64)` und Remainder-Berechnung `% modulus`.
- **Ein-Zeilen-Reproduktionsbefehl:** `cargo check -p contextra-vector --all-features --tests`
- **Geschwister-Fundstellen (R7):** `crates/contextra-graph/src/csr/graph_read.rs:398`, `crates/contextra-py/src/lib.rs:112`
- **Fix-Skizze:** `DocId::new()` Aufrufe in Testdateien auf `(i as u64).into()` anpasssen und Remainder-Cast `(id.inner() as u64) % modulus` durchführen.

### J-11-F02 (S2): Workspace-weite Unvollständigkeit der `docid-128` Fortpflanzung in `contextra-engine`
- **Schwere:** S2 (Korrektheits-/Integritätsfehler)
- **Datei:Zeile:** `crates/contextra-engine/src/transaction/compensating_actions.rs:202, 242`, `crates/contextra-engine/src/transaction/db_transaction_rollback.rs:12`
- **Beweisstufe:** [GEMESSEN]
- **Erwartet:** `DocId` lässt sich workspace-weit als `u128` verwenden, ohne `EntityId(u64)` Annahmen zu verletzen.
- **Tatsächlich:** `EntityId::new(doc_id.inner())` schlägt fehl (`expected u64, found u128`), da `EntityId` fest an `u64` gebunden ist.
- **Ein-Zeilen-Reproduktionsbefehl:** `cargo check --workspace --features docid-128`
- **Geschwister-Fundstellen (R7):** `crates/contextra-engine/src/collection/search/hybrid/query.rs:368`
- **Fix-Skizze:** `EntityId` entweder ebenfalls an das `docid-128` Feature koppeln oder explizite Konvertierung / Bounding mit Fehlerbehandlung einbauen.

### J-11-F03 (S3): Feature `memory-only-storage` ist in `contextra-store` eine inhaltslose No-Op Flag
- **Schwere:** S3 (Robustheits-/Wahrheitslücke)
- **Datei:Zeile:** `crates/contextra-store/Cargo.toml:34`
- **Beweisstufe:** [BELEGT]
- **Erwartet:** Feature `memory-only-storage` schaltet Disk-I/O / WAL ab oder schließt Datei-Operationen aus.
- **Tatsächlich:** `memory-only-storage = []` ist im Manifest definiert, wird aber in keinem `#[cfg(feature = "memory-only-storage")]` Block im Quellcode referenziert.
- **Ein-Zeilen-Reproduktionsbefehl:** `rg "memory-only-storage" crates/contextra-store/`
- **Geschwister-Fundstellen (R7):** Keine weiteren Vorkommen im Code.
- **Fix-Skizze:** Entweder bedingte Kompilierung für In-Memory Fast-Path implementieren oder leeres Feature aus `Cargo.toml` entfernen.

### J-11-F04 (S3): Facade-Feature `compliance` zieht Ring-0 Hilfscrates `audit-export` und `avv-generator` nicht ein
- **Schwere:** S3 (Robustheits-/Wahrheitslücke)
- **Datei:Zeile:** `crates/contextra/Cargo.toml:29`
- **Beweisstufe:** [BELEGT]
- **Erwartet:** `cargo tree -p contextra --features compliance -e normal` zeigt `contextra-audit-export` und `contextra-avv-generator` im Abhängigkeitsbaum.
- **Tatsächlich:** In `crates/contextra/Cargo.toml` aktiviert `compliance` nur `["sovereign", "audit-export", "avv-generator"]`, wobei `audit-export` und `avv-generator` lediglich interne Feature-Namen der Facade sind, die wiederum optionale Abhängigkeiten `contextra-audit-export` und `contextra-avv-generator` aktivieren. Die optionalen Crates fehlten jedoch in `[dependencies]`.
- **Ein-Zeilen-Reproduktionsbefehl:** `cargo tree -p contextra --features compliance -e normal`
- **Fix-Skizze:** Optionale Abhängigkeiten in `crates/contextra/Cargo.toml` eintragen: `contextra-audit-export = { workspace = true, optional = true }`.

### J-11-F05 (S4): Dokumentations-Drift zwischen Katalog und Crate-Manifesten
- **Schwere:** S4 (Kosmetisch)
- **Datei:Zeile:** `crates/contextra/Cargo.toml`, `crates/contextra-graph/Cargo.toml`, `crates/contextra-kvcache/Cargo.toml`
- **Beweisstufe:** [BELEGT]
- **Erwartet:** Feature-Katalog in der Aufgabenstellung deckt exakt die `Cargo.toml` Manifeste ab.
- **Tatsächlich:** 10 Abweichungen festgestellt (z. B. `contextra` default-features `fast, candle`; `contextra-graph` hat zusätzlich `apprh-diffusion`, `physio-percolation`, `physio-synaptic-edges`; `contextra-kvcache` besitzt zusätzlich `default`; `contextra-store` besitzt zusätzlich `legacy-wal-key`).
- **Ein-Zeilen-Reproduktionsbefehl:** `python3 /tmp/check_inventory.py`
- **Fix-Skizze:** Dokumentation und Task-Beschreibungen an den Zustand in `Cargo.toml` angleichen.

## 6. Nicht ausgeführt / Umgebungslücken

1. **Feature `cuda` in `contextra-infer-candle`:**
   - **Grund:** Baugrundumgebung verfügt über keine NVIDIA CUDA Toolchain / Driver (`nvcc` nicht im `PATH`).
   - **Befehl:** `cargo check -p contextra-infer-candle --features cuda`
   - **Benötigtes Setup:** Linux Container mit NVIDIA CUDA SDK >= 12.0.

2. **Feature `onnx` Native Libs in `contextra-infer-onnx` / `contextra-db`:**
   - **Grund:** `onnxruntime` C-Libraries / Headers nicht systemweit installiert.
   - **Befehl:** `cargo check -p contextra-infer-onnx --features onnx`
   - **Benötigtes Setup:** `libonnxruntime-dev` im System-Image.
